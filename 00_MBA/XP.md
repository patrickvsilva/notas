Método ágil (Kent Beck, anos 1990): valores + práticas que já existiam, rearranjadas num desenho. Isolada, a prática não é XP. Instância de [[Métodos Ágeis]]; o [[Manifesto Ágil]] veio depois.

## Ideia Central
Ágil é atitude; XP é o **pacote técnico**. Quatro valores (1ª ed.); a 2ª ed. (2004) acrescenta *respeito*.

| Valor | |
|---|---|
| Feedback | cliente produz e consome o incremento até aceitar |
| Comunicação | conversa > spec; o a fazer vai na [[História de Usuário]] |
| Simplicidade | só o pedido agora — não especular o futuro ([[Design de Software]]) |
| Coragem | adotar o pacote, não uma prática |

Práticas se sustentam juntas: cliente no time; TDD (teste antes); par; refatoração; código coletivo + padrão de código (≠ [[Padrões de Projeto]]); CI; ritmo sustentável. Código coletivo sem testes tensiona [[Integridade Conceitual]].

## Quando
- **Usar:** disciplina técnica e cliente no ciclo; [[Scrum]] cobre o fluxo.
- **Evitar:** prática isolada (ex.: só stand-up) e chamar de XP.
